## 1. 帳面獲利真實性（最嚴重：paper 績效結構性高估）

### 1.1 成交價用「前收」，把跳空全吃進口袋

`generate_signal` 凌晨 04:05 執行，開倉價取 0050 最近一筆收盤 =
**前一交易日收盤價**。但訊號成立的前提正是「美股夜盤大漲 ≥1.5%」——
這種夜晚 0050 隔天 09:00 幾乎必然**跳空開高**。

- Paper 帳：昨收買進 → 開盤跳空的漲幅全部入帳。
- 真實帳：最快 09:00 開盤價成交 → 跳空吃不到，只能賺「開盤後的續勢」。

台美時間差是全市場最被套利的關係之一：美股的訊息在台股開盤價裡已被定價。
**這個策略真正的 edge 不是「美股漲→台股會漲」，而是「跳空開高之後還會不會續漲」**——
而後者在文獻與實務上都弱得多（開高常見當日回補）。目前的 paper 記帳方式
把前者（拿不到的錢）記成獲利，等於績效報表在測一個無法執行的策略。
平倉同理：EXIT_ALL 在美股大跌夜觸發時，paper 用昨收賣出，真實只能賣在跳空開低後。

**這是全文件最重要的一條**：在修正成交價假設之前，paper 的任何正報酬都不能當作策略有效的證據。

### 1.2 零費用記帳

Paper 成交 `commission=0`。真實成本：手續費約 0.1425%×折扣（買賣各一次）＋
ETF 證交稅 0.1%（賣出），一趟來回約 0.25%–0.3%。回測引擎反而有算（0.1%+0.1%），
paper 沒算——兩邊還不一致。對一個單筆期望報酬可能只有 1%–2% 的訊號型策略，0.3% 是重大侵蝕。

### 1.3 回測數字不能外推

回測預設拿 QQQ 自己測（訊號與標的同源，相關性 100%），生產卻是「看美股、買 0050」；
回測有移動停利、無 S1 緩衝帶、倉位上限 0.40，生產全部相反。
回測績效與生產可得績效之間隔著至少四層假設差異（詳表見 overview §6）。

## 2. 風控缺口（獲利保護機制有名無實）

### 2.1 移動停利沒接線 = 獲利回吐無上限保護

`trailing_stop_price` 每天算、每天存 DB，但**沒有任何代碼拿它觸發平倉**
（唯一會檢查它的 `StopLossManager.should_exit` 活在無人 import 的 `order_manager.py` 裡）。
時間停損（5 天仍虧損出場）同樣未接線。

實際出場只剩兩條：固定停損 −12%、QQQ 跌破 200MA×0.98 的 EXIT_ALL。
後者是很慢的訊號：從高點回落到觸發 200MA 出場，歷史上 QQQ 常要回吐 15%–25%。
也就是說：**帳面浮盈 20% 的部位，現行系統會眼睜睜看它跌回 0 甚至 −12% 才動作**。
設計文件宣稱的「移動停利 15%」在生產上是裝飾品。

### 2.2 停損一天只看一次收盤

13:35 用收盤價檢查。盤中急殺 −15% 再收 −13%，實際成交在 −13%；
若尾盤才破線則差異小，但快市中實際虧損可顯著大於 12% 名目停損。
黑天鵝偵測在 04:07（美股側），台股盤中 09:00–13:30 完全無人看盤。

### 2.3 熔斷器未接線＋日損益算錯

`DailyCircuitBreaker`（單日 −5% 停手）在死代碼裡；而且 `update_positions` 的
`daily_pnl = total_equity − INITIAL_CAPITAL` 是**累計**損益不是單日——
就算哪天把熔斷接上，餵進去的數字也是錯的。

## 3. 結構性報酬上限（就算訊號全對也賺不多）

### 3.1 資金利用率天花板 ~30%

單一標的、無加碼、倉位上限 30%（S4 還可能壓到 15%）→ **任何時刻至少 70% 資金閒置**。
就算部位年賺 20%，對總資產貢獻只有 6%，可能跑不贏把 100 萬放債券 ETF。
空頭期（S1 BEAR）100% 現金，SHORT 訊號永遠不執行（決策矩陣沒有做空路徑），
等於一年裡有相當長時間整個系統沒有報酬引擎。保守本身不是錯，
但要用「對總資產的年化貢獻」來評估這個策略值不值得維運成本。

### 3.2 信心度加權形同虛設

BUY 倉位 = 0.25 + 信心度 ×0.05，而信心度門檻 0.6 → 實際倉位永遠落在
**28%–30% 的 2 個百分點區間**。花了一整套信心度公式，最後對部位大小的影響
小於盤中一次正常波動。要嘛讓它真的分級（例如 15%–30%），要嘛承認它只是過濾器。

### 3.3 進場與出場的時間尺度錯配

進場靠 **1 日動能**（S2：昨晚美股大漲），出場靠 **200 日趨勢**（S1 轉空）或 −12% 停損。
短線訊號的預測力（如果存在）通常在 1–5 天內衰減完畢；之後部位就是純 beta。
本質上這是「**用 S2 挑日子進場的 QQQ 趨勢跟隨策略，部位 0.3 倍**」：

- 若 S2 有短期 alpha → 現行設計沒在 alpha 衰減前收割（未接線的 5 天時間停損
  反而是對的工具，但它只砍虧損單不砍獲利單）。
- 若 S2 沒有 alpha → 它只是隨機減少進場次數的濾網，讓策略變成「打折版趨勢跟隨」。

哪一邊成立，應該用數據回答：統計歷史訊號「進場後第 1/3/5/10 天」的平均超額報酬曲線。

### 3.4 訊號頻率低，年度績效繫於少數幾筆

|NASDAQ|≥1.5% ＋ S&P500 同向 ＋ SOX 同向 ＋ 信心 ≥0.6 ＋ S1 必須 BULL ＋ 手上無倉。
低波動年份可能一季不到一筆單。樣本這麼少，勝率與期望值的統計置信度極低，
好壞一兩筆就決定全年——這不是「策略」層級的獲利引擎，比較像事件型加碼器。

### 3.5 停損停利不隨波動率調整

12%/15% 是固定百分比，不看 ATR 或已實現波動。0050 年化波動約 15%–20%：
低波動期 −12% 停損幾乎永遠不會觸發（虧損拖很久才實現），
高波動期又可能兩三天就被掃掉。倉位也一樣不隨波動調整——
同樣 30% 部位在 VIX 15 與 VIX 35 的環境下，實際風險差一倍以上。

### 3.6 訊號源與交易標的的基差風險

訊號看 NASDAQ/SOX/QQQ（美國科技股），交易 0050（台積電 ~50% ＋ 金融傳產）。
相關性高但不是 1：美股軟體股領漲而半導體平淡的夜晚，0050 未必跟。
S4 用 TAIEX 200MA ＋ 法人籌碼縮倉位是正確方向的補丁，但它只縮不擋，
且法人 5 日淨額「≥0 即滿分」的二值化太粗（買超 1 億和買超 800 億同權重）。

## 4. 次要問題（不直接虧錢，但影響判斷品質）

1. **排程每天跑，不分台股交易日**：週六凌晨也會產生訊號並「成交」在週五收盤價，
   週一才可能真正執行——又一層 paper 與現實的偏差。
2. **`daily_pnl` 是累計值**：日報 Discord 推播的「當日損益」其實是開站以來總損益。
3. **`entry_window`（09:00–09:30）與 `exit_time`（13:25）欄位無人使用**：
   規格上像日內策略的殘跡，與現行波段持有的實作不一致，易誤導讀規格的人。
4. **回測倉位上限與生產不同**（0.40 vs 0.30）：比較兩者績效時要先歸一。

## 5. 優先順序建議（供老闆決策，未動手）

| 優先 | 事項 | 為什麼 |
|------|------|--------|
| P0 | Paper 成交價改用「訊號日的 09:00 開盤價」（延後補成交或次日回填） | 不修這個，所有績效數字都在自欺；修完才知道策略有沒有 edge |
| P0 | Paper 記帳加手續費＋證交稅 | 一行費率的事，馬上讓數字誠實 |
| P1 | 決策：移動停利要不要用？要 → 在 `update_positions` 接上觸發；不要 → 從文件與 DB 顯示移除 | 現在是「以為有保護其實沒有」的最危險狀態 |
| P1 | 用歷史訊號做「進場後第 N 天超額報酬」分析 | 回答 §3.3 的 alpha 衰減問題，決定持有期設計 |
| P2 | 信心度→倉位映射拉開區間，或簡化為純門檻 | 現狀 28%–30% 沒有意義 |
| P2 | 時間停損接線（含獲利單的持有期上限一併討論） | 配合 P1 的分析結果 |
| P3 | 波動率調整（ATR 停損 / 目標波動倉位） | 結構升級，等前面都收斂再說 |

**一句話總結**：這套系統的工程紀律（fail-open、觀測層、測試）優於多數散戶專案，
但以操盤手標準看，它目前**測不出真實 edge**（成交價假設）＋**保護機制半數未接線**＋
**資金效率上限太低**。先把「量測」修對（P0），再談策略本身好不好。
