# D. 判斷力外化矩陣

> 用途：把「經驗直覺」變成可肉眼比對的判準。三個問題：該停嗎？完成了嗎？該問老闆嗎？
> 用法：不用背。卡關時讀 §1，收尾前讀 §2，猶豫要不要問時讀 §3。

---

## §1. 停損判準：什麼信號代表「方向錯了，立刻換路徑」

滿足下列**任一**信號 → 停止目前修法，回到上一個乾淨狀態（`git stash` 或記下 diff 後還原），
重新陳述問題再選新路徑。**在錯的方向上加倍努力是弱模型最大的燒錢方式。**

| # | 停損信號 | 完美正例（該這樣）| 典型反例（禁止這樣）|
|---|----------|-------------------|---------------------|
| 1 | 修 A 壞 B：第 2 次出現「修好一處、另一處新炸」 | 「兩處共用同一個底層函式，我的修法在錯的層。停下，改修底層 `_fetch_price` 一處」 | 在 A 和 B 各加一層 if 特判，然後 C 又炸了，再加第三層 if |
| 2 | 修復半徑膨脹：原本改 1 個檔，現在「還需要再改」第 4 個當初沒預期的檔案 | 「半徑超標，我的假設可能錯了。重讀報錯原文，重新定位根因」 | 「快好了，再改一個就好」（第五次說這句話）|
| 3 | 假設被證偽仍硬撐：日誌/輸出已顯示你的根因猜測不成立 | 「日誌顯示 cache 有命中，所以不是 cache 問題。放棄此路徑，改查併發」 | 「日誌可能不準」，繼續沿原假設改代碼 |
| 4 | 找不到規格中的符號：grep 整個 repo 找不到需求裡提到的函式/欄位 | 「規格提到 `stop_price` 欄位但 schema 裡沒有。這是規格與現實的落差，問老闆」 | 自己發明一個相似名字的欄位，假設「應該是這個意思」 |
| 5 | 同一條指令連跑 3 次期待不同結果 | 第 2 次失敗後就改變輸入或環境再跑 | `pytest` 連跑五次，祈禱 flaky 自己好 |
| 6 | 開始想「繞過」驗證：想跳過測試、想 `--no-verify`、想把失敗的測試改弱 | 「測試擋我 = 測試在做它的工作。修代碼，不是修測試」 | 把 `assert x == 5` 改成 `assert x is not None` 讓它過 |

換路徑後仍然卡 → 走 C 檔 §4 升級路徑（連錯 2 次必升級），不要自己硬扛。

## §2. 完成判準：滿足全部條件才可宣告「完成」

宣告完成前逐條打勾，**每一條都要有貼得出來的證據**（指令輸出原文），
「我確認過了」四個字不是證據。

- [ ] `python -m py_compile <每個改過的.py>` 輸出無錯誤
- [ ] `python -m pytest tests/unit -x -q` 全綠（貼最後一行 `N passed`）
- [ ] 改動涉及 API/前端 → 實際打過端點或 Playwright 截圖過頁面，看到預期內容
- [ ] `git status` 乾淨：無未預期的 untracked/modified 檔案殘留
- [ ] 沒有殘留 TODO / placeholder / 註解掉的舊代碼 / debug print
- [ ] 改動範圍 == 宣稱範圍（`git diff --stat` 的檔案清單與任務描述一致）
- [ ] Push 後煙霧測試 200（CLAUDE.md 開發循環第 6 步）
- [ ] `docs/PROGRESS.md` 已更新
- [ ] （若經隔離驗證）驗收官回報 PASS

**完美正例**：「完成。py_compile 無錯；pytest `42 passed`；curl /portfolio 回 200 且
00679B 顯示 33.4 非 N/A；diff --stat 只有 routes.py 與 index.html；PROGRESS.md 已更新。」

**典型反例**：「已修正 N/A 問題，代碼邏輯正確，應該可以正常顯示了。」
（零證據、用「應該」、沒跑過任何驗證——這種回報視同未完成。）

## §3. 熔斷判準：何時停止自主作業，向老闆提問

### 立即熔斷（碰到就停，不自己做決定）

| # | 觸發條件 | 原因 |
|---|----------|------|
| 1 | 動到金錢語義：交易方向、停損公式、倉位比例、風控參數、下單邏輯 | 代碼對 ≠ 策略對，賠的是真錢 |
| 2 | 資料庫 schema 異動、既有 API 回應欄位變更/刪除 | 破壞面波及前端與歷史資料 |
| 3 | 新增任何依賴套件 | 曾因套件名寫錯炸 CI（LESSONS #1）；且 256MB 記憶體經不起亂加 |
| 4 | 需要刪除 ≥ 2 個檔案，或刪任何非自己本次建立的檔案 | 不可逆 |
| 5 | 發現規格（IMPL-MAP 章節）與現實代碼矛盾 | 該改的可能是規格不是代碼，只有老闆知道 |
| 6 | 涉及密鑰/憑證/`fly secrets`/`.env*` | 紅線，settings.json 也物理擋了 |
| 7 | C 檔升級路徑走完仍失敗（兩輪重試耗盡）| 是任務定義問題，不是能力問題 |
| 8 | 品味決策：配色、文案語氣、版面取捨等無客觀對錯的選擇 | Harness 極限（A 診斷書誠實條款）：做 2–3 個方案附截圖讓老闆挑 |

### 熔斷時的提問格式（讓老闆 30 秒內能做決定）

```
老闆，遇到需要你決定的事：
【卡點】一句話說明
【我試過】嘗試 1 → 結果；嘗試 2 → 結果（沒試過就寫「未嘗試，因為○○」）
【選項】A：…（代價/風險） B：…（代價/風險）
【我的建議】選 A，因為…
```

**典型反例**：「老闆，portfolio 有點問題，你看一下。」（沒有卡點、沒有選項、
老闆還得自己爬 log——這種提問視同沒問。）

### 不需要熔斷的（弱模型常見的過度請示，直接做就好）

改註解錯字、加防禦性 isnan 檢查、補測試、按 LESSONS 已知模式修同型 bug、
更新 PROGRESS.md、按 IMPL-MAP 行號漂移更新地圖。
