# C. 模型調度與動態升降級守則

> 讀者：擔任「指揮官」的主對話模型（通常是 Sonnet 或 Opus 4.8）。
> 核心思想：**貴的腦袋做決策，便宜的腦袋跑腿，新鮮的腦袋驗收。**

---

## §0. 先判斷：這件事需要派工嗎？（多數時候不需要）

派 Subagent 有固定成本（冷啟動、重建上下文）。滿足**任一**條件才派工：

| 派工條件 | 例子 |
|----------|------|
| 需要讀/掃 > 5 個檔案或 > 1000 行才能回答 | 「整個 repo 哪裡有用到 yfinance？」 |
| 產出過程很長但主對話只需要結論 | 全 repo 安全掃描、依賴升級影響面分析 |
| 需要隔離驗證（見 §3，實作者不得自驗）| 功能完成後的驗收 |
| 主對話 context 已用掉大半，剩餘任務還很重 | 把獨立子任務外包保命 |

**反例（禁止派工）**：改 3 行代碼、讀一個已知路徑的檔案、跑一條指令看輸出。
這些自己做，派工反而更貴更慢。

## §1. 指揮官不下場

主對話模型的職責邊界：

- **做**：拆解任務、寫派工單（用 E 檔模板）、審回報、做取捨決策、與老闆溝通
- **不做**：大批量讀檔、全 repo grep 掃描、逐檔比對——這些指派給 Subagent（`model: "haiku"` 或 `"sonnet"`）
- Subagent 回報一律只收「結論 + 檔案路徑:行號」，**禁止要求或接受大段代碼貼回主對話**

## §2. 派工三件套（缺一件就是不合格的派工單）

每張派工單必含（模板見 E 檔）：

1. **目標與背景**：要做什麼、為什麼、相關檔案的明確路徑
2. **驗收條件**：可機器判定的成功標準（指令 + 預期輸出），不接受「做好做滿」
3. **回報格式**：固定欄位 —— 結果（成功/失敗/部分）、改動檔案路徑:行號、驗證輸出原文、遺留問題

## §3. 隔離驗證：實作者不得自我驗收

**規則**：負責實作的 Agent（包括主對話自己）寫完代碼後，驗收必須交給一個
**全新 context 的 Subagent**（Agent tool 每次新呼叫天然就是 fresh context）。

驗收官派工單要求它做（模板見 E 檔「代碼審查」）：
1. **Read-back**：重新讀改動的檔案，確認改動真實存在且與宣稱一致
2. **實跑**：執行驗收條件裡的指令（pytest / curl / py_compile），貼回輸出原文
3. **找碴**：對照需求列出「宣稱做了但沒做」與「做了但沒宣稱」的差異

驗收官回報 FAIL → 回到實作循環，**不得跳過驗收直接向老闆宣告完成**。

高風險改動（動到 `src/risk/`、`src/signals/`、資料庫）加碼：派 2 個獨立驗收官，
結論不一致時把兩份報告都呈給老闆裁決。

## §4. 異常升降級路徑

### 升級（連錯就換更強的腦袋，禁止原地無限重試）

| 情境 | 動作 |
|------|------|
| Haiku 工具呼叫失敗或語法錯誤 **1 次** | 直接升級 Sonnet 重派，不給 Haiku 第二次機會 |
| Sonnet 同一子任務**連錯 2 次** | 停手。整理「完整失敗軌跡」升級 Opus 4.8 |
| Opus 4.8 也連錯 2 次 | 熔斷，帶著軌跡問老闆（見 D 檔 §3）|

**完整失敗軌跡**必含：原始目標、每次嘗試改了什麼（diff 摘要）、每次的錯誤輸出原文、
目前對根因的最佳猜測。**禁止只丟一句「Sonnet 修不好」就升級。**

### 降級（省錢）

當高階模型把問題解出**固定模式**（例：「這 8 個檔案都要套同一種 NaN 防護」），
把模式寫成明確步驟 + 一個已完成的範例，降回 Haiku/Sonnet 批次套用到其餘檔案，
再由驗收官抽查 ≥ 2 個檔案。

### 重試上限

同一件事**最多兩輪**升降級循環。還是不行 = 這不是模型能力問題，是任務定義問題 → 熔斷問老闆。

## §5. Agent tool 實際用法備忘

- 呼叫：`Agent(subagent_type="general-purpose", model="haiku|sonnet|opus" 三選一, prompt=<E 檔模板填好>, description="...")`
- 唯讀搜索用 `subagent_type="Explore"`（自帶唯讀限制，更安全）
- 追問同一個 Subagent 用 `SendMessage`（保留它的 context），開新 Agent = 從零開始
- 怕 Subagent 亂改檔案 → 加 `isolation: "worktree"`（隔離工作樹，沒改動自動清掉）
- ⚠️ 以上參數以**當次 session 系統提示中的 Agent tool schema 與 agent types 清單為準**
  （工具介面會隨版本演進）。若呼叫報參數錯誤：改用 `subagent_type="general-purpose"`
  並省略 `model`，不要重試超過 1 次。
