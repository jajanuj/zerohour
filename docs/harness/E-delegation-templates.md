# E. 標準化派工 Prompt 模板

> 用法：呼叫 Agent tool 前，複製對應模板，把【】填實，整段放進 `prompt` 參數。
> Subagent 是全新 context，看不到你的對話——**【】裡沒寫的它一概不知道**，路徑要絕對明確。
> 通則：模型選擇與升降級見 C 檔 §4、§5；所有模板的回報都禁止貼大段代碼。

---

## 模板 1：搜尋研究（model: haiku 起步；結果混亂再升 sonnet）

```
【目標】在 ZeroHour repo（D:\WebSite\zerohour）中回答：【要研究的問題】
【背景】這是 FastAPI + Celery 交易系統。相關線索：【已知的檔案/關鍵字/symbol】
【範圍】只搜 【src/ 或特定目錄】，忽略 __pycache__、tests（除非問題涉及測試）
【禁止】不得修改任何檔案。
【回報格式】
1. 直接答案（≤3 句）
2. 證據清單：每條 = 檔案路徑:行號 + 該行在做什麼的一句話說明
3. 不確定之處（沒有就寫「無」）
禁止貼超過 3 行的代碼片段。
```

## 模板 2：功能實作（model: sonnet）

```
【目標】【一句話說明功能】
【背景】規格見 docs/trading-system-impl.md 第【N】–【M】行（用 Read offset=【N】 limit=【M-N】讀取，禁止整讀該檔）。
        必改檔案：【明確路徑清單】。先讀 docs/harness/LESSONS.md 避開已知坑。
【約束】
- 只改上述檔案；發現需要動其他檔案 → 停下，在回報中說明，不要自行擴散
- 遵守 CLAUDE.md 紅線（尤其：禁 git add -A；動 src/risk/ src/signals/ 公式 = 直接停）
- 不 commit、不 push——那是主對話驗收後的事
【驗收條件】（做完必須自己先跑，貼輸出）
1. python -m py_compile 【改動的每個 .py】 → 無輸出
2. python -m pytest tests/unit -x -q → 全綠
3. 【功能特定驗證，例：curl localhost:8080/api/v1/xxx 回 200 且含欄位 yyy】
【回報格式】
1. 結果：成功 / 部分完成 / 失敗
2. 改動清單：檔案路徑:行號範圍 + 各處一句話說明
3. 驗收輸出原文（上面 1–3 的實際輸出）
4. 遺留問題與風險（沒有就寫「無」）
```

## 模板 3：代碼重構（model: sonnet；涉及 >8 檔的機械套用可降 haiku，見 C 檔降級規則）

```
【目標】把【模式描述】套用到下列檔案：【路徑清單】
【範例】已完成的標準範例在【檔案路徑:行號】，長這樣：
【貼上該範例 diff 或 5–10 行成品】
【約束】
- 行為不變是硬條件：不改任何函式的輸入輸出語義，只改結構
- 一個檔案一個 commit 粒度的改動量；禁止順手修別的
【驗收條件】
1. python -m pytest tests/unit -x -q 在每個檔案改完後都要過
2. git diff --stat 的檔案清單 == 上述路徑清單，一個不多
【回報格式】
1. 每檔一行：路徑 → 套用成功/跳過（原因）
2. pytest 最終輸出原文
3. 與範例模式不符、需要人工判斷的特例清單
```

## 模板 4：代碼審查 / 隔離驗收（model: sonnet；高風險改動派兩個獨立實例，見 C 檔 §3）

```
【角色】你是驗收官。實作者宣稱完成了下述任務，你的工作是抓出宣稱與現實的差異。
       你沒有參與實作，不要腦補善意——只認檔案現狀與指令輸出。
【任務原文】【貼原始需求】
【宣稱的改動】【貼實作者的回報：檔案:行號清單】
【驗收步驟】（全部執行，禁止跳步）
1. Read-back：逐一讀取宣稱改動的檔案位置，確認改動真實存在
2. 實跑：python -m py_compile 【檔案】；python -m pytest tests/unit -x -q；【功能特定指令】
3. 反向檢查：git diff --stat 找「改了但沒宣稱」的檔案；grep 檢查殘留 TODO/print/註解掉的代碼
4. 對照 docs/harness/D-judgment-rubric.md §2 完成判準逐條打勾
【回報格式】
1. 結論：PASS / FAIL（FAIL 一票否決，只要有一條不符）
2. 證據表：判準 → 通過/不通過 → 指令輸出原文或檔案:行號
3. 差異清單：宣稱做了但沒做 /做了但沒宣稱（沒有就寫「無」）
```

## 派工單自檢（發出前 10 秒掃一遍）

- [ ] 所有【】都填實了，沒有殘留佔位符
- [ ] 檔案路徑是完整路徑，不是「那個檔案」
- [ ] 驗收條件是可執行的指令，不是「確保品質良好」
- [ ] 指定了回報格式
- [ ] 實作和驗收不是同一個 Subagent
